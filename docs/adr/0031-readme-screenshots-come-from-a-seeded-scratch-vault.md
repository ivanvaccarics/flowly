# ADR 0031 — README screenshots come from a seeded scratch vault

Status: Accepted (2026-09-22)

## Context

The README described six sections but showed none of them, and every screenshot
had to be produced by hand: start a server, click through the app, crop the
window, hope nothing sensitive is on screen. That is both slow and a small
privacy hazard — a real vault seen in a screenshot leaks real balances, real
payees and the vault id.

## Decision

- **Two scripts own the images.** `tooling/scripts/seed-demo.mjs` fills a
  throwaway vault with invented accounts, tags, rules and about three months of
  movements; `tooling/scripts/screenshots.mjs` captures the six sections into
  `docs/images/` at 1440×900 with headless Chrome. `pnpm demo:seed` and
  `pnpm demo:screenshots` are the shortcuts, and `docs/RUNNING.md` holds the
  whole recipe.
- **The seed never touches a real vault.** It only creates a vault when asked
  (`--create`) and refuses to run against one that already holds accounts, so
  pointing it at the wrong directory fails closed. The passphrase exists to open
  a scratch vault and nothing else.
- **The data is synthetic and dated relative to the run.** No provider
  identifier, no real merchant and no account number appears — the merchants are
  invented (`Market Demo`, `Metro Transit`, `Employer Inc`) and the amounts are
  generated from a fixed seed. Because the movements are placed relative to
  today, the dashboard's period, the ledger's month and the rules' coverage stay
  sensible whenever the screenshots are retaken.
- **No new dependencies.** The capture drives Chrome over the DevTools protocol
  with Node's own `WebSocket`, so the repository keeps its dependency set and the
  screenshots can be regenerated offline.
- **The README shows them honestly.** The images are captioned by what the
  section does, and the note under them says they come from a throwaway vault
  generated by those two scripts.

## Consequences

- A UI change ends with `pnpm demo:screenshots` against a seeded scratch vault,
  so the README cannot quietly show a design that no longer exists.
- The images are committed (`docs/images/*.png`, ~150 KB each at 1440×900) and
  reviewed like any other file: a screenshot that shows an empty vault is a bug
  in the seed, not in the app.
- The future desktop client can reuse the same seed data to produce its own
  screenshots with the same vocabulary.
